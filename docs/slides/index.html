Multivendor Agentic RCA for Cloud RAN

An on-demand 5G RAN and core sandbox on OpenShift, a live PTP timing-fault injection, and a governed agent that finds the root cause by collecting evidence from every vendor's layer.

For Red Hat solution architects. Source: github.com/dkypuros/multivendor-agentic-rca

1The problem

A cell goes down. In a multivendor RAN that one symptom can come from:

  • the RAN software (one vendor)
  • the cloud platform (another)
  • the timing network (a third)
  • the NIC silicon and firmware (a fourth)

Each vendor's tools see only their own layer. The NOC sees "cell unavailable".

2What we do

  1. Start a RAN slice on demand; a UE attaches with real 5G-AKA and sends traffic.
  2. Inject a timing fault: PTP goes FREERUN, the cell is locked, the O-DU raises an alarm.
  3. Run RCA: an agent gets a scoped CAPIF token, asks four planes for evidence over MCP, and a deterministic policy decides.
  4. Heal and re-check: the same agent now finds no fault.
  5. Stop: the slice scales to zero and releases its resources.

Key idea: the policy decides, the LLM only explains, and synthetic evidence never counts toward the decision.

6How the decision is made

  • Each plane returns evidence plus signals (e.g. ptp_offset_exceeded, du_sync_loss_alarm).
  • A fixed route table maps signals to a fault class (e.g. OC-TimingDegraded).
  • Corroboration counts real planes only. The bar is 3.
  • Verdicts: APPLY (auto-eligible), HOLD (needs a human), NO ACTION.
  • In the demo: RAN + PTP agree, NIC is emulated → 2/3 → HOLD. Nothing runs automatically.
  • The LLM explains the audit record. It never makes the decision.
